For Claude Code

A plan for shipping ilg.az — in parts, in order.

This document hands the design work off to engineering. It's written so you can paste any section as a prompt to Claude Code and get productive output. Read top to bottom once, then use it like a checklist.

TL;DR. Astro + TypeScript + MDX. One homepage in the Editorial theme first. Then content routes. Then the theme system. Then the four retro themes, one at a time. Ship to Cloudflare Pages. All content in MDX, no CMS. Both files — CLAUDE.md and this roadmap — go in the repo root.
§ 00 — Handoff

What you're walking out with.

Two artifacts are the source of truth for the design:

themes/default.html Retro ilg.az — Plan & Wireframes.html wireframes.jsx CLAUDE.md

Copy all four into the new repo's root under a design-reference/ folder. They aren't shipped — they're pixel-references. Claude Code should lift colors, spacing, and type scales verbatim rather than re-invent them.

§ 01 — Setup

Bootstrap the repo.

# in a fresh directory
npm create astro@latest ilg-az -- --template minimal --typescript strict --yes
cd ilg-az
npm i @astrojs/mdx @astrojs/rss @astrojs/sitemap
npx astro add mdx sitemap

# move design references in
mkdir design-reference
# copy themes/default.html, wireframes, CLAUDE.md, ROADMAP.md

# commit, push, connect Cloudflare Pages or Vercel
git init && git add . && git commit -m "scaffold"
  • Astro scaffolded with strict TS
  • MDX + RSS + sitemap integrations added
  • Design reference files committed under design-reference/
  • Deployment target chosen (Cloudflare Pages recommended — free, fast, Pages KV available for visitor counter later)
  • Domain ilg.az pointed at deploy

§ 03 — Theme contract

The rules that make five skins tractable.

Every theme honors the same token names. A page never references a hex code, pixel value, or font family directly — always a variable.

/* tokens.css */
:root[data-theme="editorial"] {
  --bg:#f6f2e9; --bg-alt:#efe9dc; --ink:#1a1714; --mute:#7a6f5f;
  --rule:#d9d0bd; --accent:#a23a26;
  --serif:'Fraunces',serif; --sans:'Inter',sans-serif; --mono:'JetBrains Mono',monospace;
  --radius:2px; --shadow:none;
}
:root[data-theme="win98"]     { /* teal, gray, Tahoma, no radius */ }
:root[data-theme="winxp"]     { /* Luna blue, Trebuchet, 3px radius */ }
:root[data-theme="terminal"]  { /* black, #33ff33, VT323, 0 radius */ }
:root[data-theme="geocities"] { /* #000080 bg, Comic Sans, ridge borders */ }

Do

Use var(--accent) everywhere. Let the theme decide.

Wrap OS-chrome in a <Window> slot component so pages don't know about chrome.

Keep content components (like <EntryList>) theme-agnostic.

Don't

Don't hard-code hex values in page files.

Don't duplicate content per theme. One posts collection renders through every skin.

Don't ship Tailwind. CSS variables are the whole trick.

§ 05 — Appendix

Things to not forget.

aSelf-host the fonts

Google Fonts goes down, gets blocked, or changes its API. Download Fraunces, Inter, JetBrains Mono, VT323 into public/fonts/ and load via @font-face. Terminal and GeoCities themes need web-safe fallbacks anyway.

bRespect reduced-motion

GeoCities marquees, terminal cursor blink, theme crossfades — all gated behind @media (prefers-reduced-motion: no-preference).

cKeep the switcher small

The switcher is a visible UI element on every theme, but it must not dominate. On Windows 98 it can live in the system tray; on Terminal it can be :theme; on GeoCities it can be a garish button. Let it speak the local dialect.

dContent first, chrome second

If a theme makes a post harder to read, the theme is wrong. Test the long-form article layout in all five before calling any of them done.

eDecide on the visitor counter honestly

The GeoCities theme calls for one. A real counter needs a KV store and a view-increment edge function. If that's too much scope, fake it with a build-time random seed that increments per day — nobody will know.

Build slowly. Ship often. The fun part is the theme switch, but the foundation is the boring part.
